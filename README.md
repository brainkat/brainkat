### 🔍 Deep Dive

#### 🛂 [Visa La Vista — AI Study-Abroad Admissions Chatbot & Voice-Based Visa Interview Simulator](https://github.com/ka-ng-ka-ng/web_visa_interview_helper)
A platform tackling the two biggest blockers for international students: scattered admissions info and a rising F-1 visa rejection rate (35% in 2025). Built as part of a 4-person team; my work focused on the AI interview pipeline and FastAPI service layer.

- **Admissions chatbot**: SQL Agent over curated university DB + LLM-driven live web search fallback for schools outside the database (LangChain + LangGraph orchestration)
- **AI mock visa interview**: STT (Vosk) → LLM-generated follow-up questions → TTS (gTTS) voice loop simulating a real consular interview, with "practice" and "real" modes
- Cross-checks spoken answers against the uploaded I-20/visa application for consistency, and scores fluency, grammar, and pacing
- Outputs a final pass/fail-style report with question-by-question feedback and recommended answers
- **Stack:** Django · FastAPI · LangChain/LangGraph · Ollama · HuggingFace · Vosk (STT) · gTTS (TTS) · AWS EC2/RDS · Docker

#### 🗳️ [Policity — AI Pipeline for a Youth Policy & News Platform](https://github.com/Policity-Project/ai_agent)
The AI engine behind **PoliTalk**, a platform that translates Korean government policy and news into digestible content and structured debate for users in their 20s–30s.

- **Card-generation pipeline**: clusters related articles by cosine similarity, filters for youth-relevance with GPT-4o-mini, and generates structured 6-tab cards (Summary / Core / Opinion / Policy / Article / Source) with automated bias detection & correction
- **RAG chatbot**: retrieves from a dual ChromaDB index (articles + cards) with profanity/abuse filtering and turn-windowed conversation history
- **AI debate engine**: supports AI-vs-AI and AI-vs-User debate modes (easy/hard difficulty) with full conversation persistence and auto-generated debate summaries
- Ran a 6-way experiment matrix (3 chunking strategies × 2 embedding sizes) to empirically select the best retrieval configuration
- **Stack:** Python · FastAPI · LangChain/LangGraph · OpenAI GPT-4o · ChromaDB · SQLAlchemy (MySQL/SQLite) · Docker

#### ⚙️ [Policity — Backend (Django REST + SSE Debate Proxy)](https://github.com/Policity-Project/backend)
Django REST Framework service that fronts the AI agent and persists all platform data to AWS RDS (MySQL).

- Streams AI debate output to the frontend in real time via **Server-Sent Events** (`httpx` streaming client → `StreamingHttpResponse`)
- Runs on Gunicorn with `UvicornWorker` to support async SSE under production load, behind an Nginx reverse proxy via Docker Compose
- Designed the `debates`, `cards`, and `users` Django apps and their REST API surface
- **Stack:** Django REST Framework · AWS RDS (MySQL) · Gunicorn/Uvicorn · Nginx · Docker Compose

#### 📊 [Policity — Data Pipeline](https://github.com/Policity-Project/data_pipeline)
Ingestion and preprocessing layer feeding structured news/policy data into the AI pipeline above.
